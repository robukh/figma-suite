# Broad run, 2026-11-16: v1.4.0 vs v2.0.0-rc1 on ten varied briefs

Ten briefs, one run per arm (20 runs), designed in the same throwaway Figma file (`HsvIin0Bb0RInkXigQUaCt`, kept for future rounds, one page per run named `bN-A` for v1.4.0 and `bN-B` for v2). Judged blind: five fresh AI judges and the project owner, on randomized unlabeled side-by-side screenshots of the **main frame only**.

**Briefs**

| | Platform | Brief |
|---|---|---|
| b1 | desktop | Project overview dashboard |
| b2 | desktop | Tasks list with filters and bulk actions |
| b3 | desktop | Billing and subscription page |
| b4 | desktop | First-run empty state for a new workspace |
| b5 | mobile 393 | Fitness app home screen |
| b6 | mobile 393 | Food-delivery restaurant detail |
| b7 | mobile 393 | Banking app main account screen |
| b8 | mobile 393 | Music app now-playing |
| b9 | tablet 820 | Flight search results |
| b10 | desktop | SaaS landing page (Tallyfox) |

Arms: `v1.4.0` (git tag) and `v2.0.0-rc1` (git tag; the version evaluated before any change from this run). Each arm was a fresh subagent with the skill's files and no user to answer questions.

| Brief | Human vote | AI judges (2 orientations) |
|---|---|---|
| b1 dashboard | tie | v1.4.0 |
| b2 tasks list | **v2** | v1.4.0 (main frame lacked the bulk-action bar; v2 put it in a state frame) |
| b3 billing | v1.4.0 | **v2** |
| b4 empty state | v1.4.0 | split by position |
| b5 fitness | v1.4.0 | v1.4.0 |
| b6 food delivery | **v2** | v1.4.0 |
| b7 banking | v1.4.0 | v1.4.0 |
| b8 music | v1.4.0 | v1.4.0 |
| b9 flights (tablet) | v1.4.0 | v1.4.0 (one judge missing) |
| b10 landing | v1.4.0 | v1.4.0 |
| **Total** | **v1.4.0 7, v2 2, tie 1** | **v1.4.0 16 of 19 votes, v2 3** |

Human and AI agree on v1.4.0 for fitness, banking, music, flights and the landing page. v2 won the tasks list and the food-delivery screen in the human vote, and the billing page with the AI judges.

## Why v2.0.0-rc1 lost

- **Platform chrome removed.** v2's subtract pass and craft floor treated the status bar, tab bar and app shell as decoration. Judges called those screens wireframe-like or fragments.
- **No icons.** The "icons in buttons: off" default became "no icons", so the music player had text links "Previous / Pause / Next".
- **Sparse screens.** Nothing pushed agents to fill the viewport; empty bottom thirds were common.
- **Main frame judged alone.** v2 moved central interactions into state frames (bulk selection on the tasks list), so the main frame looked incomplete.
- **Missing tokens, flattened design.** The fixture library has no display type, no spacing above 16 and no icons. v2 agents bound to what existed and flattened landing and consumer screens; the owner's note on the landing pair: strictness around non-existent tokens is the problem where everything is larger.
- **Process pressure.** The 17/20 pass bar was reached once in ten runs (b7), and three fix rounds plus a "remove at least one accessory" step pushed toward cutting.

Where v2 helped: it produced fewer repeated descriptions and boxes in boxes (billing), edge-case content (long names), and more state frames (loading, empty, error) on most runs.

## Mechanical scan (identical `slop-scan.js`, run on all 20 main frames by separate runners)

| | v1.4.0 | v2.0.0-rc1 |
|---|---|---|
| Frames with 0 errors | 5 of 10 | 9 of 10 |
| Errors, total | 31 (about 13 after removing false positives) | 1 |
| Advisories, total | 63 | 10 |

The error counts for v1.4.0 include a false-positive pattern (airport codes such as "JFK" read as eyebrow labels, 18 errors on one frame), "Acme" in invented merchant names, and middle-dot meta strings. The v2 numbers are not independent evidence: v2 agents ran the same scan while designing and tuned against it. More importantly, the scan only measures slop patterns, not completeness: the scan-cleaner v2 screens lost most blind comparisons.

## Caveats

- One run per arm per brief; no confidence intervals. Seven to two is suggestive, not conclusive.
- The AI judges favored fuller, busier screens (a known bias); the human vote disagreed on three briefs.
- Judging used the main frame only; v2 spent effort on state frames the judges never saw.
- The fixture design system is thin (two components, no icons, no large tokens). A richer library would change the picture, and the test of the relaxed skill should use it too.
- The slop scan was run by v2 agents while designing, so its numbers are not independent evidence.

## Round 2: relaxed v2 against v1.4.0 (same ten briefs)

Arm C is the relaxed skill (`fac438a`), run by fresh subagents on pages `bN-C` of the same file. Judged blind like round 1 (new randomization, provenance-free folders; four AI judges, two orientations, main frame only).

| b6 food delivery | **relaxed v2** (both) |
| b7 banking | split |

Effort per run (mean of 10): 234k subagent tokens, 53 tool calls, 10.9 minutes (v1.4.0: 174k, 33, 4.5; rc1: 232k, 57, 10.5). Critic scores are advisory now (16 to 20 of 24, six dimensions). Each C run reported its own slop scan at 0 errors; those numbers are not independent.

Open weaknesses the C runs reported themselves: dead space in a stretched card (b1), no payment-failed or limit-reached state frames (b3), the progress track and checkbox stroke have no tokens (recorded as T12 exceptions), and `slop-scan.js` is too long to paste twice (shorter entry point wanted). **Human vote (project owner, blind): relaxed v2 9, v1.4.0 1.** The one v1.4.0 win was the music player (b8), where the AI judges preferred relaxed v2 on both orientations. Round 1 human vote was v1.4.0 7, v2 2. Caveats as before: one run per arm per brief, main frame only, thin fixture library, the owner's vote is a single rater.

## Changes made in response (relaxed v2)

Completeness before restraint; platform chrome and a brief-coverage list required; icons allowed where the platform expects them (and creatable when missing); display type and large spacing allowed as recorded exceptions (T12); gentler subtract pass; `consumer` mode; critic scores advisory, two rounds; new scan checks (S27 mobile chrome and density, renamed-button detection, multi-frame scans).
