# Smoke run, 2026-11-16

A first, small run on a real Figma file. Not a statistical result: one brief, one run per arm, one judge (the person who ran it).

**Setup.** Throwaway fixture file with Primitives / Semantic (Light, Dark) / Spacing variables, four Text Styles, a Button set (Primary, Secondary, Ghost, `Label`), a Card with a Content slot and an icon component. Brief (identical for both arms): *"Design a team settings page for a project-management web app (desktop, 1440 wide) with a members list (name, role, last active), a way to invite a member, and a danger zone with a delete-team action."* Arms: `v1.4.0` (git tag) and `v2.0.0` (working tree). Each arm ran in a fresh subagent with no user to answer questions, one after the other, on separate pages of the same file.

## Script tests on real Figma data

| Script | Result |
|---|---|
| `verify-component.js` on Button set and Card | Worked. Correctly reported Text Styles with unbound font variables (true) and a Card slot with an unbound fill, which was real: `createSlot()` gives a slot a default white fill. Fixture fixed, gotcha added to `plugin-api-deltas.md`. |
| `slop-scan.js` on a planted-defect screen | Caught the eyebrow, restating description, nested card, two primary buttons, low contrast, placeholder text, unbound values and off-scale padding. Missed a glyph prefix (`✕ Remove`) and produced a flood of unbound-fill errors for layout wrappers with a default white fill. Both fixed. |
| `slop-scan.js` on arm A | First run saw 8 of 86 nodes: pages load lazily and the script only switched pages at the end. Fixed (switch first). Then 6 false positives (email under a name read as a restating description) and a missed pattern (subtitle under every title). Both tuned. |
| Arm B's own run of the scan | Hit the same page bug and pasted a trimmed copy to save tokens. Docs now say: paste the whole script, edit only the constants. |

## What this does and does not show

- v2 produced a visibly more restrained screen with fewer descriptions, state frames and edge content, at roughly 1.5x the tokens and 3x the time. The v1.4.0 output was already clean on the mechanical checks, so the scan alone barely separates the arms; the difference is in the judgment items.
- Arm B optimized against the scan it was given, so its 0/0 is not independent evidence. A held-out check needs a different measure (blind pairwise human preference).
- The v2 run skipped parts of its own workflow: no full scan after the last edit, no pairwise re-check, no final re-score, open P2 findings. The workflow now has a Definition of done checklist.
- The v2 run also hit instructions that assumed a user (checkpoint), a workspace (contract check) and official-skill resource access. All three now have fallbacks.
- One brief, one run each. Do the 15-20 brief evals in `evals/README.md` before drawing conclusions.
