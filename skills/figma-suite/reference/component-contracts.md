## Mapping principles

| Code concept | Figma concept |
|---|---|
| Component file | Component set on its own page |
| Union type prop (`"primary" \| "secondary"`), size prop | VARIANT property (one axis each) |
| State (hover, pressed, focused) | VARIANT state axis, or interactive component state |
| Boolean prop (`disabled`, `loading`), conditional rendering | BOOLEAN property (layer visibility or a variant-independent flag) |
| String prop (`label`, `placeholder`) | TEXT property |
| `children` / freeform content region | native `SLOT` property |
| ReactNode prop for a specific child (`icon`, `avatar`) | `INSTANCE_SWAP` property |
| `className` / style overrides | Not mapped; handled by variable bindings |

## Analysing a code component

1. **Axes.** Read the props interface and sort every prop into the table above. ReactNode props are `SLOT` or `INSTANCE_SWAP` per the [decision table](#content-regions-slot-vs-instance_swap).
2. **Visual specs.** Extract heights, padding, gap, typography, colors and radius per variant and size from the styling (Tailwind, CSS modules, styled-components). Every value maps to a token variable, never a raw number.
3. **Token map.** For each variant list fill, text color, stroke, radius and spacing variables.
4. **Matrix size.** Variants = product of all axes. Use VARIANT only for visual differences and BOOLEAN for flags such as `disabled`/`loading`, otherwise the matrix grows exponentially. Warn the user at 20 variants in one set; 30 is the hard ceiling (official `figma-generate-library`), beyond which the component must be split into sub-components.

## Structure and sizing

Name variants `Property=Value, Property=Value` and match the casing already used in the file.

Every component frame is auto-layout with padding and gap bound to spacing variables, mirroring the code's direction. Children are, in order, the content region (a `SLOT` or `INSTANCE_SWAP`, never an empty frame), text layers (TEXT property plus a Text Style), and optional trailing elements.

**Sizing contract: hug by default**, because a hidden or swapped child can only collapse the parent when the parent hugs.

| Component type | Horizontal | Vertical |
|---|---|---|
| Fully hugging (Button, Badge) | HUG | HUG |
| Dynamic-height (Card, Dialog, BottomSheet, EmptyState, Toast, multiline Input) | FIXED, or HUG when inline | HUG |
| Fixed-height control (Input, Select) | FILL or FIXED | FIXED to a spacing token |
| Child that stretches to the parent | FILL (set after `appendChild`) | per layer |

Choose HUG, FILL or FIXED per layer, not per component. A HUG parent cannot give FILL children space, so the parent of a FILL child must be FIXED or FILL.

## Content regions: SLOT vs INSTANCE_SWAP

**This table is the canonical decision rule.** Other docs link here rather than restate it. Decide per region, not per component; one component often needs both.

| The region is… | Property kind | Examples |
|---|---|---|
| A **specific swappable child component**: the consumer picks *which component* from a known set | `INSTANCE_SWAP` | Button leading/trailing icon, Avatar, Badge, a chosen CTA button |
| A **freeform content region**: the consumer authors *arbitrary content* | native `SLOT` | Card header / body / footer, Dialog body, BottomSheet content, Popover content |
| Either of the above, but **optional** | plus a `BOOLEAN` toggle | `Show Footer`, `Show Icon` |

A Card with a swappable header icon and an authored body needs an `INSTANCE_SWAP` for the icon and a `SLOT` for the body. Getting this backwards has two costs: an `INSTANCE_SWAP` body forces consumers to pre-build a component for content that should just be typed, and a `SLOT` icon loses the picker and `preferredValues`.

- Never use a raw Frame as a content region: consumers can only fill or swap `SLOT` and `INSTANCE_SWAP` properties.
- Slots get `VERTICAL`/`HORIZONTAL` auto-layout and never `GRID`; slot rules and code: [plugin-api-deltas.md](plugin-api-deltas.md#content-slots-and-instance_swap).
- Slot names are Title Case and singular (`Content`, `Header`, `Footer`).
- In `component-mappings/{id}.json`: native slots are `kind: "slot"`, swappable instances `kind: "instanceSwap"`.

## Variable binding checklist

For every component, bind and then check `node.boundVariables`:

- [ ] Fill, text fill, stroke → semantic color variables
- [ ] Corner radius → radius variable on all four corners (`cornerRadius` itself is not bindable)
- [ ] Padding (all four sides) and gap → spacing variables, choosing the semantically right token (tight gap for inline, section gap for card spacing)
- [ ] Min/fixed height → spacing variable, where applicable
- [ ] **Typography → a Text Style applied with `setTextStyleIdAsync()`.** The font variables are bound on the Text Style (`TextStyle.setBoundVariable`), never on individual text layers, because font properties are not bindable on a TextNode. Verify `textStyleId` starts with `S:`.
- [ ] Components render in one variable mode only unless `setExplicitVariableModeForCollection(collectionId, modeId)` is set on each variant; without it dark mode and themes silently show the first mode.

If no suitable variable exists, use a raw value and report it as an exception with a reason. Never skip a binding silently.

## Component composition

Composites nest instances of existing components and never rebuild them from frames; that includes icons. Reuse tokens, components and Text Styles.

**Build order** (a higher tier is never built before its dependencies; tiers are assigned by `/figma-suite setup`):

```
Tier 1 (no library dependencies): primitives: icons, badges, switches, spinners
Tier 2 (uses Tier 1):             interactive: buttons, inputs, controls
Tier 3 (uses Tier 1-2):           containers: cards, list rows, toasts, empty states
Tier 4 (uses Tier 1-3):           overlays: dialogs, sheets, navigation bars
```

**Nesting B inside A:** create an instance of B (never detach or flatten), let B fill or hug inside A's auto-layout, and expose B's key properties on A: an `INSTANCE_SWAP` to choose B's variant, a `Show B` BOOLEAN, and B's text via exposed nested properties (e.g. A's `CTA Label`; see [plugin-api-deltas.md](plugin-api-deltas.md#component-properties)).

```
EmptyState (vertical, centered)          Dialog (vertical)
├── [Icon instance]  (INSTANCE_SWAP)     ├── Title / Body  (TEXT)
├── Title, Description  (TEXT)           ├── [Button primary]  (INSTANCE_SWAP)
└── [Button]  (Show CTA + INSTANCE_SWAP) └── [Button secondary]  (Show Secondary)
```

## Verification

After creating or modifying any component, run [scripts/verify-component.js](../scripts/verify-component.js) through `use_figma` with the component or set id filled into its `NODE_IDS` constant, and report the result to the user as a table:

| Rule | Status | Actual |
|---|---|---|
| Fill bound to variable | pass | 12/12 nodes |
| Corner radius bound | pass | 4/4 corners |
| Padding and gap bound | fail | `Button/size=sm`: gap is raw 8 |
| Typography via Text Style | pass | 3/3 styles bound, 3/3 layers styled |
| TEXT / INSTANCE_SWAP / SLOT linked | pass | 3/3 linked |
| Slots: auto-layout, no GRID, wired | pass | 2/2 slots |

Fix every failure and re-run. A failure that is a deliberate exception (a decorative fill, an internal helper layer) is reported as an exception with its reason, not hidden; list all exceptions for the user.

## Accessibility mapping

| Code attribute | Figma annotation |
|---|---|
| `accessibilityRole="button"` | Annotate as interactive element |
| `accessibilityLabel` | Add to component description |
| `accessibilityState={{ disabled: true }}` | Disabled variant or property |
| `accessibilityHint` | Add to usage documentation |
| Touch target >= 44x44 | Verify minimum size in Figma |
